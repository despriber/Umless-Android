# Umless 输入法 0.1.0 真机测试清单

安装包：`dist/Umless-0.1.0-arm64.apk`（arm64，约 67MB，正式签名）。
开发时没有真机和模拟器，下面每一项都还没在手机上跑过。遇到问题时，到 App「设置 → 关于 → 导出诊断日志」导出日志（保存在「下载」目录），连同现象一起发给开发者。日志不含你说的原文和 API Key。

## 0. 安装与首次启动

- [ ] 能安装（ColorOS 可能提示「未知来源」，允许即可）；桌面图标是青绿色声波图标，名称「Umless 输入法」
- [ ] 打开后直接进入新手引导，页面适配手机屏幕，没有左右滚动
- [ ] 引导第 1 步「启用键盘」：点按钮能跳到系统的输入法管理；开启 Umless 返回后状态自动变为「已完成」；「切换为 Umless 键盘」能弹出输入法选择框
- [ ] 第 2 步「麦克风权限」：弹出系统授权框；授权后麦克风测试有声波，音量提示合理（此时还没下载模型，只测音量、不出文字是正常的）
- [ ] 第 3 步「识别模型」：下载约 166MB，进度正常，完成后显示已下载（注意流量；中途切走 App 再回来，进度能接上或给出明确错误）
- [ ] 第 4 步「润色」：填你的 OpenAI 兼容接口（地址、Key、模型），「测试连接」能返回润色示例
- [ ] 第 5 步「试一试」：在引导页的输入框里长按空格说话，能看到「原文 → 输出」对比

## 1. 键盘基础（它首先是一个输入法）

- [ ] 拼音打字、候选词、标点、数字键盘、切换中英文都正常
- [ ] 默认是 Umless 浅色 / 深色主题，随系统深色模式切换
- [ ] 空格左右滑动移动光标仍然可用；短按空格正常输入空格
- [ ] 键盘上方工具栏有麦克风按钮
- [ ] 长时间打字后，其他 App 被杀后台的情况没有明显变多（语音模型只在最近 15 分钟用过语音时才常驻内存）

## 2. 语音输入（核心）

在微信、QQ、备忘录、浏览器地址栏、邮件里分别试：

- [ ] 长按空格：键盘顶部出现「正在聆听」、声波和计时；说完松开 → 识别中 → 润色中 → 文字写入光标处
- [ ] 松开后不会多出一个空格
- [ ] 按住时手指上滑：提示变为「松开取消」，松开后什么都不写；滑回去可以继续
- [ ] 按得太短（不到 0.3 秒）直接放弃，不报错
- [ ] 写入后约 4 秒内出现「原话 / 撤销」：点「原话」换成识别原文，点「撤销」删掉刚写入的文字
- [ ] 有拼音还没上屏时长按空格说话，拼音被正确清掉，不会和语音结果混在一起
- [ ] 工具栏麦克风打开语音面板：按住大按钮说话同样能用，面板显示最近一次的原文和润色结果
- [ ] 第一次说话（或很久没用后）从松开到出字的等待时间可以接受；连续说话时明显更快
- [ ] 断网或大模型出错时：仍写入识别原文，并提示「润色失败 / 超时，已输入原文」
- [ ] 密码框里长按空格只提示「密码框不支持语音输入」，工具栏没有麦克风按钮
- [ ] 微信里说话时，识别结果不会莫名丢失；「原话 / 撤销」不会立刻消失
- [ ] 第一次在键盘里说话时如果录到的全是静音（一直提示「未识别到内容」），请导出日志反馈

## 3. 隐私

- [ ] 浏览器无痕标签页里说的话：照常输入，但「历史」里没有记录
- [ ] 设置 → 隐私里把某个 App 加入黑名单（填包名，如 `com.tencent.mm`）：在它里面说的话不进历史
- [ ] 暂停记录后说的话不进历史；恢复后正常记录
- [ ] 导出数据、清空数据可用

## 4. 主 App（与桌面端相同的界面）

- [ ] 概览、报告、练习、历史、设置五个标签都能打开，深浅色正常，底部导航不被系统手势条遮挡
- [ ] 历史：每条记录高亮口癖 / 重复 / 改口，可搜索、删除
- [ ] 报告：当天说够 3 条以上后可以「诊断今天」，生成评分、问题、示例和习惯卡
- [ ] 练习：出题 → 限时口述 → 评分与示范表达
- [ ] 设置 → 键盘：长按空格说话、工具栏麦克风、震动三个开关生效
- [ ] 设置 → 关于：「导出诊断日志」能保存到「下载」目录；「高级键盘设置」能打开 fcitx 原有设置
- [ ] 返回键：在设置详情页返回到列表，在首页返回退出 App
- [ ] 键盘提示「请先下载模型 / 允许麦克风」时，点提示能跳回 Umless 对应页面

## 5. 稳定性

- [ ] 手机重启后、解锁前（锁屏输入密码时）键盘能正常打字，不崩溃
- [ ] 系统清理后台后，再次长按空格说话仍然可用
- [ ] 切换深浅色、旋转屏幕后主 App 页面不丢失

## 6. 应用更新（0.1.2 起）

需要 GitHub 上有一个比手机上更新的正式 Release（含 `update.json` 与同一签名的 apk）；也可把配置 `update.manifest_url` 指向自建的测试清单。

- [ ] 0.1.1（versionCode 112）能直接覆盖安装 0.1.2（10022），数据保留
- [ ] 打开主 App：开启「自动检查更新」且距上次超过 24 小时时，主界面出现新版本提示条；关掉网络时不报错、不打扰
- [ ] 「检查更新」手动检查：显示新版本号、更新说明（随界面语言）、大小
- [ ] 下载：进度正常；中途断网 / 切走再回来，再点下载能从断点继续（不从 0 开始）
- [ ] 首次安装：没有「安装未知应用」权限时跳到系统设置页「允许来自此来源的应用」；打开开关返回 Umless 后再点安装能继续（ColorOS / Android 16 上重点看这一步，设置页能否直接定位到 Umless、返回后是否回到 Umless）
- [ ] 系统弹出安装确认界面（「要更新此应用吗」）；点更新后 App 被结束，重新打开是新版本，数据、设置、模型都在
- [ ] 确认界面点取消：不弹错误提示；再点安装还能再次弹出确认界面
- [ ] 第二次更新（此时 Umless 已是自己的安装来源）：Android 12+ 上是否不再需要确认（系统决定，不需要也算正常）
- [ ] 签名不同的安装包（例如用调试签名或别的密钥打的同版本号更高的包放进自建清单）：下载后提示「签名与当前应用不一致」，不会进入安装
- [ ] 更新成功后再打开主 App，`cacheDir/updates` 里的旧安装包被删除（设置 → 应用 → 存储里的缓存变小）
